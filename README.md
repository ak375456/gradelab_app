# GradeLab

The non-linear editor supports **additional videos, image/video overlays, layer visibility/locks/order, transforms/blending, markers, beat-aware audio, text and shape layers** alongside non-destructive per-clip grading. Separate linked sound or import MP3/M4A/AAC/WAV/AIFF; trim, split, move, copy/cut/paste, duplicate and delete audio on waveform tracks. The compact Audio tab offers live volume/mute and beat markers, with a shared preview/export mix. Text clips support multiline typography, bundled/custom TTF fonts, presets, color, stroke, background, shadow, glow, curve and export rendering. **Shape layers** draw rectangles, ellipses, triangles, stars, polygons, arrows and capsule lines with a flat or gradient fill, stroke, corner radius, star waist, shadow and glow. Text and shapes are one concept in the code — a drawn overlay — so they share placement, trimming, splitting, the canvas handles and all three compositing paths (SDR, HDR and Apple Log) rather than each having its own. **Keyframe animation** covers text transform and appearance properties, shape geometry and appearance (size, corner radius, star waist, fill, stroke, shadow and glow), video/image transforms, and **colour grading** — light, colour, all twenty-four HSL values, the three colour wheels, the vignette, look strength, the finishing effects and all ten curves — with Linear/Hold/Ease curves evaluated identically in preview and export — see [the keyframe system](Docs/KEYFRAME_SYSTEM.md). Grading animation is one more consumer of that engine rather than a second one: a grading parameter is an ordinary animatable property whose storage is `GradeSettings`, so it inherits clip-relative timing, trim/split/retime behaviour, undo and persistence unchanged. Masked local grades animate through the same tracks. See [migration design and checkpoint](Docs/TIMELINE_MIGRATION.md). Animated audio volume, discrete (step) animation of font/bold/alignment, a graph editor and advanced audio effects remain future work.

GradeLab is a native iOS and Mac Catalyst video color-grading app built with SwiftUI, AVFoundation, Metal, VideoToolbox, ImageIO, PhotosUI, and Photos. It implements one complete workflow: import a real video, inspect its metadata, grade decoded frames on the GPU during playback, export those frames through the same grading function, then inspect, save, or share the generated movie.

**Still photographs** go through the same grading system. Importing a photo opens a workspace with the picture, the Color tab and the scopes — no timeline, no transport, no duration — and every control is the one video uses, writing into the same `GradeSettings`, so a preset or a copied grade crosses between a clip and a photograph in either direction. The picture is decoded once with ImageIO into the Rec.709 working space, graded by the same Metal functions through the same renderer, and exported at the source's own resolution as JPEG, HEIC or PNG. Full-resolution export renders in tiles with frame-absolute coordinates and a halo blurred once over the whole picture, so the exported file matches what was on screen; `Scripts/ValidateStillImage.swift` proves that on the GPU. Photographs carrying an HDR gain map — nearly every recent iPhone photo — are graded as the SDR picture the file is built around, with the import stating that the gain map is not carried through. Raw files, and images whose primary data is PQ/HLG-encoded, are refused with a reason rather than flattened.

## Open and run

Open `dummy name.xcodeproj`, select the shared **GradeLab** scheme, and run on iOS 18 or later, or choose **My Mac (Mac Catalyst)** for macOS 15 or later on an Apple silicon Mac (M1 or later). Intel Macs are not supported. Mac imports open the system file browser; Photos remains available from Home. See [Mac setup and release steps](Docs/MAC_RELEASE.md). The project container retains the starter project’s filename, but the app target, product, module, bundle display name, and shared scheme are all named GradeLab.

Command-line verification:

```sh
xcodebuild -project "dummy name.xcodeproj" -scheme GradeLab \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build

xcodebuild -project "dummy name.xcodeproj" -scheme GradeLab \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build-for-testing
```

## Video colour and export support

GradeLab has validated grading paths for tagged 8-bit Rec.709 SDR, higher-precision Rec.709 SDR, 10-bit HLG/BT.2020 HDR, and Apple Log. Apple Log is identified from the file's Log transfer-function metadata, decoded with Apple's published curve into scene-linear BT.2020 for grading, and rendered to Rec.709 for preview and 10-bit Rec.709 export. Preview can explicitly interpret an 8-bit source with incomplete colour tags as Rec.709, but export remains blocked until the stream declares the colour properties needed to verify the result.

Apple Log 2 is identified separately and deliberately remains unsupported. It uses a different transfer curve and Apple Gamut primaries, so GradeLab never sends it through the original Apple Log/BT.2020 transform. PQ/HDR10, Dolby Vision metadata preservation, unknown camera Log profiles, unverified bit depth or colour metadata, source tracks whose format changes mid-stream, and files containing multiple embedded video tracks are also rejected rather than silently converted through the wrong colour pipeline.

Export offers hardware HEVC Main/Main 10 or H.264 High in MOV/MP4, plus ProRes 422 and ProRes 422 HQ in MOV on compatible devices. Available codecs depend on the source colour mode and device capabilities. Original/720p/1080p/4K/custom-long-edge sizing, original or 24/25/30/50/60 FPS, three quality levels, and optional average bitrate are supported where applicable. Resizing preserves aspect ratio; custom FPS drops/repeats frames without changing speed. Original settings retain geometry and timestamps. Rotation and readable audio tracks are retained; audio is re-encoded as AAC. For iPhone camera files containing normal and Spatial Audio presentations, only enabled audio tracks are exported. Native PCM samples are passed through to the AAC encoder without a sample conversion. Contradictory mono/stereo PCM channel-layout metadata is removed from the writer format hint; valid layouts are retained. No lossless or universal-format claim is made.

## Editor revision

The Color workspace has nine tools: Light, Color, Curves, HSL (eight hue ranges), Wheels (shadows/midtones/highlights), Local, Vignette, Effects, and Look. **Local** is a soft ellipse or rectangle that limits a clip's creative grade without changing its transparency. The editor also has a separate top-level **Mask** tool beside Transform. That mask changes the selected video or image layer's alpha, so clips on lower tracks become visible through an ellipse, rectangle, or infinite Linear/Split mask; it includes direct preview dragging, position, size, rotation, feather, inversion, and per-property keyframes. Linear Position X keyframes produce a standard swipe transition. Color → Local position, size, rotation, feather, and opacity use the same keyframe engine. **Curves** covers ten control-point curves — Master, Red, Green and Blue for tone, and Hue vs Hue, Hue vs Saturation, Hue vs Luma, Luma vs Saturation, Saturation vs Saturation and Saturation vs Luma for colour — with monotone cubic interpolation, an eyedropper that samples the graded frame to build a three-point hue selection, and correct wrapping across the red 0°/360° boundary. See [Architecture](Docs/ARCHITECTURE.md) for the interpolation, LUT layout and pipeline position. Look applies one of three bundled creative LUTs — Warm Cinema, Teal Orange, Soft Film — at an adjustable strength; the look runs before the other tools, so they adjust its result. The LUTs are original 33-point `.cube` files generated by `Tools/LUTGenerator` for Rec.709/SDR footage, not camera or colour-space conversions. Your own 3D `.cube` looks can be shipped with the app by dropping them into `LUTSources/Imported/` and running `Scripts/compile-luts.sh` — the app discovers every bundled look at launch, so no code change is needed — or imported on the device from Files via **Look → Import**, which validates them, stores them in Application Support, and lets them be removed again. Bundled looks ship compiled: `.cube` text is the source, and the `.gclut` the compiler writes holds the same 16-bit samples the GPU uploads, which is bit-identical to parsing the text and about 79% smaller. See that folder's `HOW_TO_ADD_LUTS.md` for which downloads work and which do not. Every numeric grading control carries the same keyframe diamond the Transform tools use, and each of the ten curves keyframes as a whole snapshot rather than per control point: two snapshots need not share a topology, because the blend samples both curves and interpolates the heights. Hue values take the shortest path around the circle, so a wheel animating from 350° to 10° passes through red rather than unwinding through cyan. Copy Grade and Save as Preset stay static: they carry the base grade, never clip-relative keyframes. Each tool includes a usage guide and panel reset. Hold the preview for Original; release for Edited, or toggle the compare button. Paused display ticks retry late decoded frames/drawables while skipping unchanged GPU work.

No simulator is needed for the current manual acceptance pass. `build-for-testing` only compiles the tests. `Scripts/ValidateGrade.swift` is a host Metal regression harness for grading math and model compatibility; it does not test iPhone playback or hardware export. `Scripts/ValidateLUT.swift` is the equivalent harness for the look stage: it compiles the real shader, uploads the real `.cube` files, and checks identity round-tripping, stored-entry accuracy, strength blending, endpoints, bypass and persistence on the GPU. `Scripts/ValidateCurves.swift` does the same for the curve stage: interpolation behaviour, exactness of the legacy tone-curve migration, hue continuity across the 0°/360° seam, and each of the ten curves through the real `applyGrade` on the GPU. See the device checklist for those tests.
